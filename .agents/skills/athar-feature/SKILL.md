# Athar — build a feature phase (post-P34 pattern)

## Order of work (never reorder)
1. **Proposal first** (`P<N>-PROPOSAL-AR.txt`, Arabic, 1–2 pages): the idea in one sentence, the five "movements" of the experience, what stays private, what gets signed, what the agent may read, what the cron does, the DB tables, the constants. Wait for approval. Read `athar-product` before writing it.
2. **Read**: `AGENTS.md`, the previous two phases (`lib/org-pair/*`, `lib/pair/*`, `lib/org-horizon/*`, `lib/horizon/*`; `lib/journey/load.ts` `loadJourneyInput` is the single source of a person's events, `lib/org-journey/load.ts` `loadOrgJourneyInput` of an organization's; `lib/org-impact/auth.ts` `orgCtx` for org-admin auth; `lib/pair/*` for anything with **two parties** — `sideOf/other/nameFor`, `findCircle`, blind invitations, a single row carrying invite → live → review states; `lib/org-pair/*` for **person↔organization** — asymmetric kinds per side, `orgViewFor` stripping per side, one component with two faces `side='member'|'org'`) — copy their shapes, not older ones. An organization-facing feature is a **tab inside `/org`** (`app/org/page.tsx` + `?tab=`) rendered by an `app/components/OrgX.tsx` component, not a new top-level page; a member-facing echo of it is one banner component on `/me` (`OrgPledgeBanner` pattern, `?mine=1` endpoint).
3. **SQL** `supabase/migrations/YYYYMMDD_portal_pN.sql` (see `athar-sql`): tables with `user_id uuid` + `email text` (legacy rows have no user_id), `status text check (…)`, `meta jsonb default '{}'`, RLS own-read, `revoke` writes from anon/authenticated when only the server writes, extend `portal_vc_issuances_kind_check` if a new signed document kind is added, ONE diagnostic `union all` at the end with expected counts.
4. **Pure library** `lib/<module>/registry.ts`: constants (`*_DAYS`, `*_MONTHS`, `MAX_*`, `K = 5`), types, builders from plain inputs, validators returning `string | null` (Arabic), code formats (`ATH-XX-XXXX-XXXX` via `randomCode(4)` from `lib/portal/profile.ts`), local (non-AI) text builders. No DB, no `process.env` → unit-testable.
5. **DB layer** `lib/<module>/load.ts` (reuse `loadJourneyInput(db, me)` instead of re-querying events; a personal "state" loader returns `{ input, chapters, <current>, <past> }`) (`Promise.all` of `.or(\`user_id.eq.${id},email.ilike.${email}\`)` queries, every query wrapped so one failure yields `[]`), `share.ts`/`badge.ts` for signed documents (copy `lib/journey/share.ts`: insert issuance → `signDocument` with `status_index` → update `vc` + `documentDigest`), `cron.ts` exporting `runX(db, { dry, site, now })` returning `{ ok, counts…, errors[] }` — every scheduled effect must be idempotent (`meta.nudged_at`, status transitions, `.gt('review_at', now)` guards) because the daily cron re-runs; dry runs count only.
6. **AI (optional)**: `runAi({ system, user, parse, local, budgetMs, fast })` + `logAi(db, {...purpose})` from `lib/ai/athar.ts`. Always provide `local` fallback; feed only anonymized text or the user's own words; label the result (`source: 'ai' | 'local'`); never persist without a user action. Reuse an existing `AiPurpose` from `lib/ai/prompts.ts`.
7. **API** `app/api/<module>/route.ts`: `runtime='nodejs'`, `dynamic='force-dynamic'`, `maxDuration=60`; `svc()` service client for tables **after** the route authorized the caller, but **any RPC that authorizes itself via `auth.uid()`/`auth.jwt()` (`portal_org_dashboard`, `portal_impact_report`, …) is called on the user's session client (`userDb`) and its `ok` is checked before the result reaches a page** (917–919); `who(req, db)` accepting both Bearer users and `delegateFromHeaders` with the right `pscope`; delegates may only read; `limitFor(db, 'council_write_ip', ipOf(req))` (or a new named bucket in `lib/shield/ratelimit.ts`) on POST; `{ action }` switch; `confirm: true` required for anything that publishes/signs/seals; public reads return `Cache-Control: public, s-maxage=…` + `Access-Control-Allow-Origin: *`; private reads `no-store`. Log learner actions to `portal_learning_events`.
8. **Pages**: learner `app/me/<module>/page.tsx` (`'use client'`, `PortalShell`, `useLang`, `fastToken(db)` from `app/components/Pocket.tsx`, `Channel` for any text/voice/video input, `data-testid` on every interactive block, `<style dangerouslySetInnerHTML>` with a unique class prefix; success/flash messages keep their timer in a `useRef` and clear the previous one — a bare `setTimeout` wipes the next message). **Gate screens** (eligibility not met) must be actionable: honest distance («بقي N فصول»), the three fastest real routes as direct buttons with ✓ on what already exists (needs the API to return *kinds*, not just a count), and a clickable preview of every movement behind the gate (`MOVES` + `pp-step-N` pattern in `app/me/pair/page.tsx`) — the owner's first real visit to P29 looked «broken» without these (P29-أ); public `app/<module>/[code]/page.tsx` (`useParams`, explicit 404/410 states); admin page only when staff must decide something.
9. **Patches** (each is a whole-file replacement): `app/me/page.tsx` nav tab · `lib/portal/mcp.ts` tool entry (`tiers`, `pscope`, `kind: 'personal'`, `readOnlyHint`) · `lib/portal/mcp-server.ts` handler via `internal(c, '/api/<module>?view=summary')` · `lib/vault/registry.ts` one RoPA row per new personal table (unit test fails otherwise) · `app/api/followups/send/route.ts` cron hook + result key · `PortalAdminTabs.tsx` if admin page.
10. **Tests** `tests/pN.test.ts` (copy `fakeDb` from `tests/p26.test.ts`; `assert.ok` always with a message; pin `now` and pass it to `structuralChecks(doc, now)`), import in `tests/index.ts`.
11. **Mock**: `tools/mock-supabase.py` — add the new tables to the insert whitelist and a defaults branch (bigserial vs uuid ids!), copy the patched mock back to `dashboard-redesign/tools/` immediately.
12. **QA** per `athar-qa` (after any patch to a built clone: stop `next start`, `rm -rf .next`, rebuild — edits are not picked up by a running build), then **E2E** `tools/shot-pN.py` (API checks + OAuth delegate flow + cron + Playwright screenshots). Look at the screenshots. Include an **empty/real-shaped organization** fixture (one admin, no members, no events) and open every `/org` tab — the P24–P28 org UI ran against a real org for the first time on 2026-10-30 and crashed on a shape the seeded fixtures never produced.
14. **Production smoke with the demo org**: after deploy, open `/org` as the owner (org «جامعة أَثَر», a fictional demo organization) and click every tab; the global `app/error.tsx` boundary will show the exact `TypeError` if something is off — read it before touching code.
13. **Package** `dashboard-redesign/phase6-pN/`: `files/<repo paths>`, `pN-code-only.zip` (zip `app lib tests` from inside `files/`), `NNN-pN-<name>.sql` + `.sql.txt` twin, `MANIFEST-PN-AR.txt` (numbered: SQL, NEW files, MOD files, sha256 each, next number), `STEPS-PN-AR.txt` (SQL → expected counts → upload zip → verify URLs), `SHA256-PN.txt`, `shots/`. Present the zip, then SQL and STEPS.

## Conventions that bit us
- Keys that can repeat (same skill approved twice) must include the distinguishing value (`level_approved:<skill>:<level>`).
- `Record<string, IconName>` for icon maps; `Icon` names are a fixed union.
- Routes must never export anything but handlers/config.
- Arabic in HTTP headers → `encodeURIComponent`.
- Browser caches `s-maxage` responses → client fetches needing fresh state use `cache: 'no-store'`.
- Cron runs other syncs first (e.g. مِعيار placement) — E2E expectations must be computed after the cron, not hard-coded.
- Mock `/auth/v1/user` returns the admin for ANY token → test 401 without a token, not 403 for other users.
- Event-derived progress compares ISO strings against `signed_at` **and** `now` — E2E fixtures dated in the future are invisible; seed events between the signed date and now.
- Buttons inside dark cards need their own `light` variant in the page CSS (`pt-btn ghost` is navy-on-white).
- Link only to routes that exist in `app/` (`/#daily`, `/sim`, `/me/data`, `/councils`, `/me/missions`, `/me/pair`) — `/me/daily`, `/me/vault` and `/simulations` never existed (898–899, P29-أ). This applies to **step guides sent to the owner** too: `grep` `app/**/page.tsx` before writing a URL.
- Rate limits: reuse `limitFor(db, 'council_write_ip', ipOf(req))` for personal writes; E2E runs need a fresh `X-Forwarded-For` per step group.
- Service key ≠ user: under the service role `auth.uid()` is null. RPCs with internal `portal_is_staff()/portal_is_org_admin()` checks silently return `{ok:false,error:'forbidden'}` → `d.members.filter` crashed `/org` in production (P8 code, found in P28). The mock now answers `forbidden` to `Bearer svc` on `portal_org_dashboard` so E2E catches a regression.
- `/org` loads the first org's dashboard asynchronously and re-selects it; Playwright tests that switch organizations wait for `oh-scenario|oh-elig` + ~900 ms before `select_option` (`go_org` helper).
- Pages never assume API shapes: guard `if (!j.x || j.x.ok === false || !Array.isArray(j.x.items)) throw new Error(...)` and show the message; the app-wide `app/error.tsx` (self-contained, inline CSS, no imports) is the last line, not the first.
- Organizations exist in production only when seeded by SQL (`portal_organizations` + confirmed `org_admin` membership, `source='admin'`). Before saying «works», confirm the feature has data to run on.
- A gate with two conditions shows both honestly (`members n/5 · chapters n/2` dot rows) — never collapse them into one «not eligible».
- Chapter-producing actions have precise moments: «كل يوم مهارة» on the first answer; simulation only when the run **ends** (`ended_at`/`status ended|scored`); mission only on supervisor **confirmation**; council on active membership. Say so in UI copy and guides («يُكتب الفصل عند الإنهاء لا عند البدء»).
- Two-party features: the second party in E2E is `browser.new_context()` + `wait_for_load_state('networkidle')` after login; the mock login maps email → token (`noura@` → `tok-u2`, `khalid@` → `tok-u3`). Blind rows (invitee not in circle / not eligible / already paired) return the **same** reply and send **no** notification — assert both.
- E2E assertions after an action wait for the resulting element, never a fixed sleep and never a bare `.pp-ok` (stale message from the previous action). Prefer a `wait_for_function` that reads `textContent` over `:has-text("…")` with Arabic diacritics (P30: `has-text` missed «أُرسلت خطوتكم»). After an action whose reload is slow (member GET recomputes chapters ≈ 2 s), wait for the element the fresh state renders (the quote, the step card), not for the success message alone.
- «Past» lists require the real milestone (`accepted_at`/`signed_at`); cancelled or declined invitations are not past pledges.
- Document kinds live in **two** places: the SQL `portal_vc_issuances_kind_check` constraint (migration) and `lib/portal/vc.ts`'s kind list/verify page labels — update both and assert `vc_kinds` in the diagnostic.

- One component, two faces (P30 `OrgPair.tsx`): when the same card serves both sides, name the columns by **what they hold** (the «ask» column is always the org step, the «mine» column always the member step) and derive labels from `side`; deriving the *content* from `side` swapped the columns and showed the option list in both. Options cached in `meta` per side are cleared by a rework — the UI must offer «اقترح لي» again, and the API answers 409 to a propose without options.
- Deep links from notifications must be honoured by the target page: `/org` ignored `?org=<id>` for years (opened the first org); read `window.location.search` in the first effect and pre-select (960).
- **WCAG 2.2 AA is part of done** (standing rule since P30): a 3 px `:focus-visible` ring on every control of the new CSS prefix, text + `aria-label` beside colour dots, `role=status` messages with a labelled close button and no auto-timeout, `radiogroup` with `aria-label`, ≥ 24 px targets. The E2E asserts the dot text and tabs into the component to check `outlineWidth === '3px'`.
- Notify **both** parties on the moment that completes a shared artifact (second signature, joint decision) — P30 first notified only the party who did *not* act; assert both `to_email`s in E2E.
- A public-facing registry (P31 `lib/directory`): one row, two faces — never two tables for «experts» and «trainers». Keep three views in the pure lib: `publicView` (strips contact/staff/meta, applies per-section visibility), `ownerView` (no `staff_only`), staff (everything). Derived «witness» lines come from records only; the member may hide the block, never edit a line. Order public lists by `updated_at desc, name` — no stars/ranking/featured.
- Labels for closed-list codes (services, modes, domains) must reach **every** surface that prints them: the public page, the owner form groups and the admin list (P31 shipped raw `pedagogy`/`consulting` twice before E2E screenshots caught it). Return `*_ar` maps from the API rather than translating in each page.
- Scope "no email/phone" assertions to the component (`dir-card`, `vc-summary`), never the whole body — the footer contains `info@athar-portal.sa`.
- Admin lists with a default filter (`submitted`) hide rows in E2E after the flow finished — click «الكل» (last `.am-filters` button) before waiting for rows.
- Anything copied to a public bucket on approval must be removed on suspension/withdrawal/erasure and re-published on reinstatement; assert `photo_public_path` null/non-null on both transitions.
- Camera/file inputs (P31-ب): hidden `<input type=file>` keeps its `data-testid` (Playwright `set_input_files` works on hidden inputs); «التقط» uses `getUserMedia` on fine pointers and `capture="user"` on coarse ones; E2E launches Chromium with `--use-fake-ui-for-media-stream --use-fake-device-for-media-stream` and a context `permissions=['camera']`, waits for `video.videoWidth > 0`, then snaps to a JPEG `File`.
- AI that fills a form (P31-ب `parse_cv`): the API returns `fields` + `filled_keys` + `notes_ar` + `source`; the page merges (empty-only by default, `overwrite` opt-in), keeps a `prevForm` ref for «تراجع», and never saves. Add the purpose to `AiPurpose`, `AI_LIMITS`, `AI_PURPOSE_LABEL` and the `/ai` services table; log counts only. Attachments go through `runAi({ attachments })`; Word is unpacked by `docxText` (no npm). Vercel body limit 4.5 MB → cap files at 3 MB before base64.
- Cross-cutting phases (P32 `lib/inclusion`): keep ONE pure registry of codes + Arabic labels + hints (`NEEDS`, `FEATURES`, `NEED_FEATURES`) and reach every surface from it; the UI state lives in a context (`AccessProvider`) that mirrors to `localStorage` **and** `<html data-access="…">` so CSS does the adaptation (`html[data-access~="low_vision"] .pt{zoom:1.25}`), with account sync only after login (account wins over device).
- Sensitive-by-law data (needs, health-adjacent): never put it in an AI prompt, never in an org view, never in a VC; staff see k≥5 aggregates or explicit opt-in (`share_staff`) scoped to a program; the public stats endpoint returns `null` below quorum; write a unit test that asserts the AI prompt builder receives only public text.
- Anything AI writes for the public is `pending` until staff approve/edit (`portal_access_texts`); the public GET returns `{text:null,pending:true}` — test that state explicitly.
- A skip link must be the first focusable element on **every** page: put `SkipLink` in both shells (`PortalShell` and `GlobalNavigation`), self-styled (`<style>` inside the component) because `ACCESS_CSS` is only injected by the portal shell; E2E: `pg.keyboard.press('Tab')` then read `document.activeElement.textContent`, press Enter and assert `activeElement.tagName === 'MAIN'`.
- Dialogs: `role=dialog` + `aria-modal` + focus trap (Tab/Shift+Tab wrap) + Esc + return focus to the opener; E2E presses Tab 40× and asserts `activeElement.closest('[data-testid="ax-panel"]')`.
- Browser-only capabilities (speech recognition, speechSynthesis) are feature-detected and explain by text when absent; broadcast results on the existing room channel (`caption` event) — no server, no audio leaves the device.
- Controlled checkboxes bound to the URL (`?fit=1` via `router.replace`) fail Playwright `check/uncheck` («did not change its state») — use `click` + `wait_for_function` on the resulting DOM.
- Admin lists sorted by name: never rely on `.first` in E2E — add `data-pid={id}` and target `[data-pid="p1"]`.
- Mock ids are string UUIDs: never `Number(body.id)` in admin routes (prod bigint ids still parse); and every new table must be added to the mock's generic-insert list or inserts vanish silently.
- Renames are text-only deliverables: change labels, titles, comments and test names; never rename `data-testid`s, tables, API actions or codes (P32-ب: «على مقاسي» → «احتياجاتي» touched 9 files, zero logic).
- Presence features (P33 `lib/onair`): presence is one row per person toggled by the person (`until` timestamp, auto-off by reading, never by cron); time-outs are settled on read (`settleStale`) so no cron is needed; anonymous askers hold a per-request token in `localStorage` (`athar_onair_t:<id>`) and are rate-limited by `ip_hash` — E2E reruns need a unique `X-Forwarded-For`.
- Hours and certificates come from real meetings (`taken_at → done_at`, `duration_min`), never from how long a toggle was on; seconds-long E2E meetings round to 0 h — assert meeting counts, not hours.
- Extending a live feature (P34 — eight ideas in one phase): keep ONE registry of Arabic names (`P34_NAMES_AR`) exposed in `?meta=1`, one migration with `add column if not exists` + new tables, and extend the existing route actions instead of new routes; reuse the existing cron entry (`runDirectory` → `remindGolden`) rather than adding a Vercel cron.
- Matching may use a *preference* the asker states in the request (`prefer_text`) but never a stored need-word; dialog defaults derived from needs (`dialogDefaults`) are computed in the browser from `GET /api/inclusion?mine=1` and the need is never posted.
- AI drafts that become public content (P34 «صدى السؤال»): asker consent (`echo_ok`) → staff `echo_make` (PII-scrubbed prompt, local fallback) → staff edits + picks a day → `approved` → the public consumer (`/api/daily`) prefers it and marks it `published`. Approving without a day must be a 400.
- Read-only observers (shadow mentor): expose `i_shadow` in the request view, return 403 on write, show a tag and hide the composer; decrement a per-mentee counter on `take`, not on close.
- Scoped calls (org air): the scope is validated against confirmed membership on `ask` (400 otherwise); the read endpoint lets staff read any scope and members only their own (403) — test the 403 with a non-staff user (staff users pass).
- Name fallbacks are contextual: `loadPeople(…, withProfiles=true)` only where a non-directory person must be named (mentor/mentee); public surfaces keep «طاقم أَثَر».
- Maps: an inline SVG with a short list of city points keyed from the public directory city (`cityKey`), counts only, «مدن أخرى» for the rest, `aria-label` with the total; never coordinates of a person.
- A 409 that offers an alternative (`{nobody:true, can_bottle:true, bottle_ar, alternatives_ar}`) is a product state, not an error: the dialog renders the offer and the retry posts the same payload with `bottle:true`.

## Delivery message (Arabic)
Table (number · path · role), QA line (tsc · tests N/N · build · E2E N/N), "ideas that emerged" (the owner welcomes them), then the 3 steps (SQL with expected counts → upload zip → verify URLs). After «تم»: verify every file with `cmp` against `raw.githubusercontent.com/<sha>/<path>` (URL-encode `[`), check the Vercel status API, smoke-test live routes, and close the phase explicitly with the next file number.

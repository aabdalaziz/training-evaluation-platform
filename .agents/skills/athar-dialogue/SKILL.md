# Athar — the dialogue loop (P51–P66)

Read `docs/ATHAR-DIALOGUE-LOOP-P51-P63-AR.txt` (and the data-travel matrix `docs/diagrams/athar-dialogue-travel-matrix.svg`) first; this skill is the operational checklist.

## The loop in one line
Trainer writes/speaks a «كلمة» (P51/P55) → learner answers with a touch/line/voice «أمانة» (P53/P54) → learner gets a weekly 🪞 «صدى» (P56) → the organization gets a monthly «رسالة الشهر» with an aggregated «نبض» (P52/P57) → the learner weaves their own «خيوط» into «خريطة أثرك» (P58) → the trainer reads what the section wove together in «نسيج الشعبة» and answers with a 🧶 word on it (P59) — which is again a «كلمة», so the loop closes on itself. The learner can also speak each «لأن…» (P60) — voice stays with its owner only. At program level the kept threads become **counted** evidence in the living accreditation file «نسيج البرنامج» (P61) — never quoted. On the program's last day the learner's own words come back to them as a page they curate, seal and may open to the world: «يوم تخرّجي — بكلماتي» (P63).

## Non‑negotiable rules (every new piece must honour all of them)
1. **Nothing enters evaluation.** No column read by `lib/portal/skills.ts`, `lib/journey/registry.ts` scoring, مِعيار, or credentials may be written by the loop. Say so in the UI footer and in the release doc.
2. **k ≥ 5** for anything shown to an organization or the public (`K_ORG = 5` in `lib/org-impact/registry.ts`). Below k: show the privacy mirror sentence, never a number.
3. **No names** outside the author's own screen: «مدرّبك», «زميل», «جلسة». Public faces hide sensitive titles (daily cases → topic via `topicOf`).
4. **Voice** = private bucket `athar-media`, path `word-voice/<trainer_id>/…`, signed temporary URLs, 180‑day purge in the existing media cleanup, limits `TRAINER_VOICE_LIMITS` (20 s) / `VOICE_LIMITS` (15 s · 10/h). Browser dictation (Web Speech) is allowed for text fields; never store new audio without a human listener on the other side.
5. **No server AI** in the loop. Rules must be explicit and visible to the user («حدث ثم حدث خلال N يومًا»).
6. **Dedupe + ≤ 1/day** for every notice kind (`dedupe_key` on `portal_learner_notices`); reuse the daily cron `/api/followups/send` — never add a Vercel cron.
7. **Delete is immediate** (no recycle bin); «declined» choices are never re‑proposed.
8. **Zero new env, zero deps, one SQL first** (with expected diagnostic counts), `.txt` twin for every `.md`.

## Where things live
- Pure cores (unit‑testable, no DB): `lib/portal/day.ts`, `lib/portal/word-reply.ts`, `lib/portal/week-echo.ts`, `lib/org-impact/{letter,pulse}.ts`, `lib/map/registry.ts`, `lib/map/weave.ts` (section aggregation: `weave` · `groupKey` · `orgStrongestThread` · `peersOf`), `lib/map/program-weave.ts` (program aggregation: `programWeave` · `weaveEvidence` · `programPeersOf`).
- Glue (DB, auth, storage): `lib/map/store.ts`, `lib/map/nudge.ts`, `lib/map/weave-load.ts` (roster = `collectDayBook` classrooms · P58 maps in batches of 6 · consented notes always read fresh), routes under `app/api/me/*`, `app/api/org/*`, `app/api/admin/org/*`, `app/api/verify/*`.
- UI: `app/components/{VoiceRecorder,EchoSay,LetterSheet,AtharMapSvg}.tsx`; learner pages under `app/me/*` load heavy desks with `next/dynamic({ ssr:false })`.
- Notice kinds: extend `NoticeKind`, `KIND_AR`, `KIND_ICON` in `lib/portal/notices.ts` together.
- New routes → `lib/portal/way.ts`; new tables → `lib/vault/registry.ts`; voice aliases → `lib/portal/voice.ts`.

## Aggregating learner-authored content (P59 pattern)
- **Consent is a column on the learner's own row** (`portal_map_threads.share_trainer` + `shared_at`, check `share_trainer=false or status='kept'`), default off, revocable instantly, withdrawn automatically when the row leaves the «kept» state. Never cache consented text — cache only the heavy part (maps) and re-read consents on every request.
- **Roster = the same source the trainer already sees** (`collectDayBook` → enrollments ∪ attendance). Do not invent a second membership query; two screens showing different counts destroys trust.
- Aggregates: stations shown only when ≥ k learners reached them; threads `woven` (kept ≥ k) / `untaken` (kept 0 and offered ≥ k); 1–4 keepers are invisible, not «nobody». Personal stations (`credential:`/`badge:`) group by title, individual ids (`mission:`/`hand:`/`horizon*`) by kind, daily cases by topic (`groupKey`).
- Quotes: none before k distinct consenters; ≤ 10; order seeded by day so timing never leaks. No name, no date, no counts below k anywhere in the payload (test the raw JSON for emails).
- The trainer's answer must re-enter the loop as an ordinary `trainer_word` (`meta.weave=1`, dedupe `weave_word:<trainer>:<email>:<day>`) so replies/echo/pulse keep working untouched.
- Org admins get one sentence in the monthly letter (`pulse.thread_ar`, `manual` excluded, k ≥ 5) — never the weave itself.

## Voice that never travels (P60 pattern)
- Voice is identity: a learner's recorded «لأن…» is stored in the private bucket under `map-voice/<user_id>/<row_id>.<ext>` and exposed to the owner only (signed URL, 5 min). It never enters the weave, the letter, the snapshot or `/verify/*` — only a count line («N من خيوطك بصوتك»). Guard this with a raw-JSON test (`!/map-voice|note_voice|"voice"/`).
- One file per row; re-record replaces and removes the old object; `decline`/`remove` of the row removes the object too. Client payloads carry `{sec, at}` only — never the path.
- Keep browser-side libs light: a file imported by a client component must not import server chains (`word-reply` → `practice` → …). Duplicate the few constants and pin them with a unit test against the server source of truth.

## Counting without quoting (P61 pattern — program-level aggregates)
- Scope of consent is literal: «شارك كلمتي مع مدرّبي» authorises the trainer's weave only. Any other reader (accreditation file, ETEC reviewer, public strip) gets **counts only** — `lib/map/program-weave.ts` never reads `note_ar`/`note_voice`, and the raw-JSON test asserts no email, no note, no voice path.
- A thread belongs to a program when one end is one of its stations (`scopeKeys`: `program:<pid>` · `session:<id>` from `attendance_sessions`/`portal_sessions` · `mission:<id>`); `manual` is excluded; rows are deduped per (learner, from, to). Learners are the program's enrollments (`approved|placed|active|completed`), cohort = year of `placed_at || created_at`.
- Evidence attaches itself (`weaveEvidence` → `kind: 'weave'`, `href: '#weave'`) under ETEC sub-standards per rule (`WEAVE_EVIDENCE_CODES`) and only at n ≥ k; «graduates still weaving» = roster learners who decided any non-manual thread after `programs.end_date` → 3.5. It flows through `collectEvidence`, so coverage, freeze (`weave_ar`/`weave_n` in the snapshot body), `/verify`, the public strip and `/admin/accreditation` all see it without extra plumbing.
- Transparency back to the learner: `/api/me/map` returns `program_peers` («خيطك جزء من نسيج برنامج … — نسجه معك N») computed from counts on the program key excluding the learner; a silent aggregate is not an honest one.
- Cache only the heavy part (10 min per program, `fresh` bypass); never store the weave in the DB.

## Second edition, not a second table (P62 pattern — «رسالة إلى نفسي بعد سنة»)
- Before adding a feature, grep for its ancestor: the P25 time capsule (`portal_time_capsules`, `/api/journey`, `runJourney`) already held «رسالة إلى نفسي بعد سنة». P62 extends that table with `ALTER … ADD COLUMN IF NOT EXISTS` (horizon · opened_at · opened_early · reply_ar · chain_of · prompt_key · context_key · program_id · scope) and backfills `context_key='journey'`; old capsules appear in the new desk untouched.
- The sealed body never leaves the server: `toPublicLetter` strips `body_ar`/`media_id` until `opened_at` is set; the E2E asserts the seeded sealed text is absent from the raw GET JSON. Early opening is allowed but honest — `opened_early=true` + `early_days`, shown as «فُتحت قبل أوانها».
- Opening hour = writing hour (Riyadh): `deliverAt(written, horizon, programEnd)` adds days or takes `programs.end_date` at the same HH:MM:SS; `grad` falls back to the nearest **future** end_date only, and must be ≥ tomorrow.
- Mirror «ما حدث فعلًا» = counts only from the learner's own rows (chapters · skill levels · credentials · councils · letters) — no percentages, no verdicts, no AI. `snapshot_now` is stored at opening so the mirror never drifts.
- Voice capsules: `portal_media.expires_at` (+180 d) + `media_cleanup` would delete audio before a 1‑year letter opens → `keepMedia` pushes `expires_at = deliver_at + 400 d` and tags `context_type='self_letter'`. Any future deferred feature with media must do the same.
- Cohort envelope «رسالة الدفعة»: one line per graduate per program (`scope='cohort'`, unique partial index), 10–160 chars, no email, opens 1 year after `end_date` at 09:00 Riyadh and only at n ≥ 5 (deterministic shuffle, no names). Writers can delete their own line until the envelope opens.
- Cron key `self_letters` (after `org_letters`) only pushes the notice on the opening day (`todayNoticeText`, dedupe `self_letter:<id>`); it never opens the letter for the learner — the learner opens it.
- Limits are part of the design: ≤ 3 sealed letters, delete is immediate (text + media), `rateLimit('letter:<uid>', 3600, 20)`, audit kind `self_letter`.

## The learner's own words, curated by the learner (P63 pattern — «يوم تخرّجي — بكلماتي»)
- **Only learner-authored items** enter the page: `buildCards` reads the learner's first «لأن…» (`portal_map_threads.note_ar`, kept, inside the program window), their text replies (`portal_word_replies.text`), their journey chapters, their cohort line (P62 `scope='cohort'`), the state of their `grad` letter (never its body), their map snapshot code. Trainer words are excluded — except one **«كلمة الوداع»** the trainer sends with `grad: true` from «دفتر اليوم» (`trainer_word` with `meta.grad=1`, dedupe `grad_word:<classroom>:<email>`), shown first and clearly attributed.
- The page **opens on `programs.end_date`** (`programWindow` = start → end+1 day; `gradPhase`: `before|today|after`) for every graduate — past ones included — but the cron (`runGradDays`, key `grad_days` after `media_cleanup`) notifies **only** today's graduates (`grad_day:<enrollment_id>`, push) and the trainers of classrooms ending in 3 days (`grad_word:<classroom_id>`, no push, url `/me/day?grad=<cid>`). No retroactive notices.
- Curation = `keep` (a jsonb of `key:false`) + «سطر التخرّج» (10–160 chars, `validateLine` rejects emails/urls) + an optional 🎙️ ≤ 15 s stored at `grad-voice/<user_id>/<row_id>.<ext>` that is **never** part of the sealed body nor the public face (the raw-JSON E2E asserts `voice` is absent from `/verify/grad`).
- Seal = `ATH-GD-XXXX-XXXX` + `sha256(jcs(body))`, body `{v:'p63', code, program, name, line_ar, cards, counts, sealed_at}`; editing after sealing only marks `seal.stale`; resealing pushes `{code, sealed_at, digest}` into `history` so the old code verifies as `revoked + replaced` (`.contains('history', JSON.stringify([{code}]))` — supabase-js turns a JS array into `{…}` postgres syntax, so pass the JSON string). Revoke is immediate and public; delete removes row + voice object.
- **Public face `/g/<code>`** is off by default (`live_public=false` → «خاصّة بصاحبها»); when on, `PUBLIC_DEFAULT = ['line','counts']` and everything else (`name`, each card, `since`) is an explicit opt-in (`public_keys`). `publicFace` never emits email, voice, or hidden cards.
- «منذ ذلك اليوم» = counts only (`sinceThen`: threads after end, stations reached, letter/envelope opened, days since); cohort line «N من دفعتك ختموا» only at n ≥ 5 live seals (revoked excluded); the org pulse reads `portal_grad_pages` directly (a client-imported lib like `pulse.ts` must not import `lib/grad/store.ts` → `node:crypto` breaks the browser bundle); accreditation evidence `kind:'grad'` under ETEC 3.5 at n ≥ k through `collectEvidence`.
- The older P39 after-letter is **not migrated**: `lib/letters/legacy.ts` reads `portal_after_letters` read-only, SelfLetter shows it under `sl-legacy`, and the P39 write form in `/me/after` became a door to `/me/letter?door=grad&program=<pid>` (legacy `letter_write` stays dormant, not removed).

## Closing the circle — zero tables (P64 pattern — «أول يوم — قال من سبقك»)
- **Grep the ancestors first**: «سنة أولى»/«أول يوم» already existed as a P62 door (`DOORS_AR.first_day`) and P38 program excerpts; P64 is a *composition* of P63 (public lines), P38 (`programAfterOf`), P51 (`sendWord` + `meta.welcome`) and P62 (`writeLetter` with `context_key='first_day'`). No migration, no env, no cron key beyond `first_days` (after `grad_days`).
- **Open with the institution's own word** before any data: `atharWelcome(firstName, programAr)` is a static, human-authored block («شكر وتقدير وأمنيات», signed «— أَثَر»), personalised only by first name (session name → enrollment `full_name` fallback) and program name. Never generated.
- «قال من سبقك» = `predecessorLines`: `portal_grad_pages` with `live_public=true`, sealed, not revoked, for the program **and every program with the same `name_ar`** (older cohorts under another id); the line comes from the sealed `body.line_ar`, one per `user_id`, shown only at ≥ 5 people, ≤ 7, shuffled by `fnv(program:day)` so order never leaks timing; the payload carries strings only (E2E greps the raw JSON for names/emails/codes). The same function feeds the public program page through `programAfterOf().said` (lazy `import('../first/store')` to avoid the import cycle).
- «لماذا جئتُ» is a P62 letter, not a new row type: `writeWhy` → `writeLetter({horizon:'grad', program_id, prompt_key:'why_came', context_key:'first_day'})`; `writeLetter` validates it with `validateWhy` (10–160), excludes `first_day` rows from the ≤ 3 sealed limit (server **and** `SelfLetter` client count), one per program, window = start → start+7 days (`firstPhase`: `before|first|week|later`), never retroactive. On graduation day it surfaces as card `first_why` in P63 (`loadSources` splits `caps` by `context_key` so `grad_letter` never mixes with it).
- Trainer «كلمة الاستقبال» is an ordinary `trainer_word` with `meta.welcome=1` (title «🌅 كلمة الاستقبال من مدرّبك…», url `/me/first?program=`, dedupe `welcome_word:<room>:<email>`), opened from `/me/day?welcome=<classroom_id>` (checkbox `dy-welcome`, exclusive with `dy-grad`); it shows in «أول يوم» and becomes P63 card `welcome`.
- Cron `runFirstDays`: 🌅 `first_day:<enrollment_id>` (the only pushed one) on `start_date` = today Riyadh; `welcome_word:<classroom_id>` to the trainer one day before; `line_awaits:<grad_row_id>:<day>` to graduates whose line is public when a new cohort of ≥ 5 starts and lines are shown — counts only («سطرك ينتظر N متدرّبًا»), never who read.
- Program lineage by `name_ar` is deliberate and visible in the code comment; if the institution renames a program the older cohorts simply stop feeding the strip — nothing breaks.

## Time is not contiguous (P66 pattern — «أيام التدريب وفترات التطبيق»)
- A program's `start_date → end_date` is only a container. **`portal_room_calendars`** (one row per classroom: `days[]` sorted, Riyadh day keys) is the truth about *when the room actually meets*; `deriveCalendar` turns the days into `blocks` (gap ≤ 2 days joins — a weekend inside a block is still the same block) and `applies` (gap ≥ 7 days = an application period with weeks numbered from the day after the last block day). No calendar ⇒ the room is treated as contiguous and **everything older behaves exactly as before** (`has_calendar:false`, `allowed:['learn']` while the program runs).
- `phaseOf(cal, today)` → `before | training | apply | rest | after | none`; it is the only place that decides *what kind of line may be written today* (`allowedKinds`): `learn` on a training day, `+commit` on the **last day of a block that is not the last block**, `apply` during an application week. Routes never re-derive this.
- **Overlay, don't migrate**: P63/P64 (`first/grad store.ts`) and letter horizons (`lib/letters/store.ts`) call `datesOverlay`/`overlayCalendars` so the first/last *calendar* day replaces the program dates per enrollment (`calendar_first`/`calendar_last` kept beside the originals). The cron (`runRoomCalendar`, key `room_calendar` after `first_days`) sends `first_day`/`grad_day` through the calendar **only when it differs** from the program dates — same dedupe keys as P63/P64, so a learner never gets two first days.
- One table for all learner lines: `portal_learning_lines(kind learn|apply|commit, day, body_ar ≤ 200, blocker_ar, block_no, apply_no, week_no, opens_on, done)` with `unique(user_id,classroom_id,kind,day)` → writing twice the same day is an upsert (`updated:true`), and an apply line is keyed by the **week start**, not the calendar day. `commit` carries `opens_on = next_block_start` and is **unreadable by anyone but its owner, and by the owner only from that day** (`open` is computed server-side; the trainer sees `commits_pending` as a count).
- The trainer's «ما جرى في الميدان» (`fieldSummaryOf`) is the P59 aggregate pattern again: shown at ≥ 5 people, ≤ 5 lines shuffled by `fnv(classroom:apply_no)`, **blockers are a second k-threshold** (`blockers_people ≥ 5`, otherwise only the count in `below_ar`). It is pushed to the trainer as `field_summary:<cid>:<apply_no>` exactly 3 days before the block returns (`CAL_LIMITS.summaryBeforeDays`) and opened from `/me/day?room=<cid>#calendar`.
- Learner notices are quiet by design: `apply_start:<enr>:<n>` (🧭 once per period), `apply_week:<enr>:<n>:<w>` only on the week start and only if ≥ 3 days remain, `commit_open:<line_id>` on the day the block returns. Nothing on rest days; nothing after the program.
- Calendar authoring is the room trainer's or staff's (`canEditRoom`): pattern (`start, block_len, every_weeks, blocks`), count (`start, n`, Fri/Sat skipped) or free text (`parseDays` accepts `2026-11-10` and `10/11/2026` / `10.11.2026` in any prose; no ranges — write each day), ≤ 400 days, always previewed before `window.confirm`. Clearing a calendar keeps the lines.
- Lessons that cost a run: fixed-date tests must pass `expandDays(…, false)` (2026-11-20 is a Friday); `cleanLine` truncates to 200 so `validateLine` checks the **raw** length; `/me/line` sorts rooms by what is actually waiting (`commit_open` → has calendar → writable today → rest), and the mock's نورة is `PROGRAM_MANAGER` (staff) — use ريم (`tok-u5`) to test a plain learner's 403.

## A diploma is a structure, not a longer course (P66-ب pattern — «هيكل الدبلوم»)
- Hierarchy in one line everywhere: `structureLine()` → **«الدبلوم : المستوى N — المقرّر — شعبة N — أستاذ المادة»**. Levels live on `portal_program_units.level_no` (≤ 8), the instructor on `units.trainer_id`, the section number on `classrooms.code` (**last** number in the code: `D3-2` → «شعبة 2»; else `section_name`). Short courses never set `level_no` and keep «وحدة/مدرّب» — `is_diploma` is derived, not stored.
- **No academic defaults in code.** `validateSlot` rejects a schedule row without `starts_at` (HH:MM) and `minutes` (20–300); forms render those inputs empty. A course may be 50 min, another 110; Ramadan/exams are `portal_schedule_periods` (`lecture_minutes/first_lecture_at/lecture_break_min/shift_min` inside `from_day..to_day`) applied by `lectureOn()` at generation time without touching the base row. `lecture_break_min` is informational only.
- Lectures are **materialized** `portal_sessions` rows (`kind class`, `series_id = slot id`, `unit_id`, `title = course`, `description_ar = structure line + room`, `starts_at` stored as Riyadh ISO `…+03:00`). `generateLectures` is future-only: delete `series_id` rows with `starts_at ≥ riyadhIso(now)` then insert what is still ahead (`Date.parse` compare, never string-compare mixed offsets). Saving a slot, a period, or adopting a proposal regenerates; the running lecture and the past stay as they happened.
- Conflicts are **warnings, never blocks** (`conflictsOf`: same instructor or same section overlapping on the same weekday) — the supervisor decides. `suggestGrid` is a greedy constraint fill (courses × sections over weekdays × supplied times, instructor/section free) returning `{proposed, unplaced, note_ar}`; nothing is saved until `adopt`. Human approves, always.
- The learner's day line gets a `unit_id`: «قبل أن تغادر» is one `learn` line per course per day (`portal_learning_lines_one_idx` is `(user_id, classroom_id, kind, day, coalesce(unit_id,''))`), only writable when a lecture of that course exists that day (`lectureExists`). The next lecture opens with the **course thread** (`courseThread`: P59 aggregate, k ≥ 5, no names) — the same thread feeds the instructor's «الممرّ» card (`corridorCard`) in the day book between two lectures.
- Section membership is for the whole level: `portal_section_requests` (reason 5–200, one open per enrollment, status `open|done|declined`) → coordinator = `classrooms.trainer_id` (notice `move_request:<id>` → `/me/diploma?program=<id>#requests`); `done` moves the enrollment and resets `placed_at`; the learner hears back via `move_decided:<id>`.
- «البديل بلمسة»: `substitutesFor` lists instructors of the program free at that slot's time on that day; `applySubstitute` patches **one** session row and notifies the section (`substitute:<session_id>:<enrollment_id>`, url `/me/line`). «وضع الوردية»: `shiftDayFor` keeps the day line open until `quiet_to + shiftGraceDay` for learners with a quiet window — no new prefs.
- Voice: «ماذا عندي اليوم» stays `/me/day`; «محاضراتي اليوم / وش عندي اليوم / جدولي اليوم / قبل ان تغادر / شعبتي» → `/me/line#today` (aliases must not contain «من» — the parser strips it). API `/api/diploma` GET `?program=|?list=1|?today=1|?corridor=<session_id>`; rate key `diploma:<uid>` 60/h; cron key `level_close` right after `evidence`.
- Lessons that cost a run: the mock compares timestamps as strings — keep one ISO format per table and pass `riyadhIso(now)` to `gte('starts_at')`; `sectionLabel` must take the **last** digits of the code; store tests need a fake-db chain with thenable `limit()`; P39/P63 E2E read admin's `/me/day` sessions list — any new seeded `portal_sessions` row shows up there.

## Signed documents pattern (P52 letter · P58 snapshot)
Code `ATH-XX-XXXX-XXXX` (alphabet without 0/1/I/O) + `sha256(jcs(body))` + `/verify/<kind>?code=` page that never shows private content unless the owner made it public. One live document per period (partial unique index `… where revoked_at is null`); re‑sign revokes the previous; revoked → the verify page says «أُبطلت». Do **not** reach for `lib/portal/vc.ts` unless a third party needs a W3C VC.

## Service clients in GET routes
Use a `noStore` fetch (`global: { fetch: (i, init) => fetch(i, { ...init, cache: 'no-store' }) }`) for any route that must read freshly updated rows (public/revoked flags); Next 14 may cache identical upstream GETs otherwise.

## Tests
- Unit: one `tests/pNN-*.test.ts` with a fake db (`from(table)` builder supporting `select/eq/neq/is/in/gte/lt/or/not/order/limit/maybeSingle/single/insert/upsert/update/delete/then`) — upsert must return the stored row with `id`, else `pushNotice` reports `duplicate`.
- E2E: `tools/shot-pNN.py` — API first, then browser (desktop + mobile ≤ 392 px scrollWidth + `pageerror` empty). Wait on DOM state, not fixed timeouts (API POSTs that rebuild a journey take ~2 s).

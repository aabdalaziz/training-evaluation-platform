## 1. What this repository is
- One Next.js 14 (App Router, TypeScript) + Supabase (Postgres, Auth, Storage, RLS) application deployed on Vercel (Hobby). Zero runtime npm additions since P1.
- Two faces, one codebase:
  - **Public portal «أَثَر»** at `/` — the institution homepage and the whole learner/organization/agent experience (P1–P38, see §6).
  - **Evaluation platform «منصة التقويم»** — the original training-evaluation product (surveys, attendance, impact follow-up, certificates, KPIs, reports). It remains one service of the portal. Do not break it.
- Production: https://athar-portal.vercel.app (alias: training-evaluation-platform.vercel.app). Supabase project `nybinzuqwhcctgwcimru`. 96 `portal_*` tables, all with RLS (+ storage buckets: private `athar-media` for uploads incl. CV photos, public `athar-public` for approved directory photos only).
- Language: Arabic-first (RTL) with English parity on the public portal. Admin and learner pages are Arabic. **Terminology matters**: official professional names in contracts/certificates/admin UI; narrative names only on the homepage, `/2062` and «أثير». Renames already applied: «هندسة البرامج التدريبية» (not مصنع), «الميسِّر» (not الطيار المساعد), «مؤشر الأداء» (not طقس).

## 2. Non-negotiable rules
1. **No new npm dependencies.** Use `fetch`, Canvas, WebCrypto/`node:crypto`, built-ins. PDFs on Canvas (`lib/certificates/render.ts`), Excel via `lib/export/xlsx.ts`, Ed25519 via `lib/portal/vc-server.ts`.
2. **No new Vercel cron jobs and no new env vars** unless the owner approves explicitly. Scheduled work piggybacks on the daily `/api/followups/send` chain (see `runCouncils`, `runJourney`, `runOrgJourney`, `runHorizon`, `runOrgHorizon`, `runPair`, `runOrgPair`, `runDirectory`, vault/observatory/outreach runners) — add a `runX(db, { dry, site })` and wire it there.
3. **Whole-file deliverables.** The owner edits only through the GitHub website. Deliver one code zip with `app/ lib/ tests/` at its root (dragged into `/upload/main` → one commit), SQL as a separate `.sql` + `.txt` twin, and Arabic step guide. Dot-dirs (`.agents`, `.well-known`) go through `/new/main?filename=` or `/edit/main/...` links. Numbering is global and sequential (next number is stated in the latest `MANIFEST-P*-AR.txt`; after P31 and P31-ب it is **990**).
4. **SQL migrations are idempotent** (`if not exists`, `create or replace`, DO blocks for constraints/policies) and end with ONE `union all` diagnostic query whose expected counts are stated in the step guide. Commit a copy under `supabase/migrations/`.
5. **Row Level Security on every new table.** Learner rows: `user_id = auth.uid()` (+ email fallback where legacy rows have no user_id). Writes go through server routes with the service role; `revoke insert, update, delete … from anon, authenticated` when the client must never write.
   - **RPCs that check `auth.uid()` / `auth.jwt()` inside (e.g. `portal_org_dashboard`, `portal_impact_report`) must be called with the user's session client (`userDb`), never with the service-role client** — under the service key `auth.uid()` is null, the function answers `{ok:false,error:'forbidden'}` and the UI crashed on the first real organization (fixed in 917–919). Any route that forwards an RPC result to a page checks `ok` first and returns 403/500 with an Arabic message. The local mock now reproduces this (`Bearer svc` → forbidden).
6. **Zero hydration errors.** `<style dangerouslySetInnerHTML={{ __html: CSS }} />`; client-only values start as `null` and are set in `useEffect`; page files export only the default component (+ `dynamic`/`runtime` when needed).
7. **Every pushed file is verified** byte-for-byte (`raw.githubusercontent.com/<sha>/<path>` + `cmp`) and Vercel status checked via `api.github.com/repos/.../commits/<sha>/status`.
8. **Bilingual by construction** on public surfaces: `T = { ar, en }` + `t(x, lang)` from `lib/portal/content.ts`; dates in `toLocaleDateString('ar-SA-u-nu-latn-ca-gregory')`; currency via `money()`.
9. **Future-proof data model**: skills first-class (`portal_skills`), unified sectors, `portal_learning_events` (xAPI-like: `verb, object_type, object_id, skills[], context`) for every learner action, `portal_organizations` for B2B. New content carries `sector`, `skills[]`, `level`, `delivery`, `ai_ready`, `lang`.
10. **Product principles (since P10, owner-approved — never violate):**
    - **AI assists, a human approves.** Computed levels ≠ approved levels. AI output is labelled and editable; nothing AI-written is published or stored as fact without an explicit user/staff action.
    - **No personal identifiers reach AI models.** Anonymize («عضو 1/2…») before `runAi`; declared in `/.well-known/privacy.json`.
    - **k ≥ 5 (and ≥ 2 organizations where relevant) for any aggregate shown to anyone else.** Never lower it for small groups — say «below quorum» honestly instead.
    - **Private by default; selective disclosure; revocable.** Shares/badges/charters are Ed25519-signed OpenBadge documents (`portal_vc_issuances`, kinds `credential|snapshot|dataset|council_badge|org_charter|journey|org_journey|horizon|org_horizon|pair_pledge|org_pair_pledge|directory_card|collaboration`), verifiable at `/verify/vc?code=`, and revocation is always one click.
    - **Compare only with self**, never rank people or organizations.
    - **The user's own words only.** Quotes attributed to a person come from their own text; a peer's words are never attributed to them.
    - **Derived from events, never self-reported.** Progress («الدرب») is computed live from recorded events after a signed date; no progress bars, no percentages, no «mark as done» buttons. For an organization the path is **distinct-people counts (k=5) only — never member names, not even for the org admin** (P28).
    - **Gates are earned, not bought.** A horizon or mutual pledge opens only after real chapters (person: 3 — for **both** parties of a pair; organization: 2 chapters **and** 5 confirmed members; person↔organization pledge (P30): the member's 3 chapters **and** the organization's **signed charter** — «جهة لم تَعِد نفسها بميثاق لا تَعِد منسوبًا»). Show the honest distance (`n/5 · n/2` dots) instead of unlocking on request — **and** (lesson of P29-أ) every gate screen shows the shortest concrete path with direct buttons (✓ on what already exists) plus a clickable preview of what lies behind the gate; otherwise the page looks broken.
    - **Between two humans the platform only witnesses.** In person↔person features (mutual pledge) no AI touches the words («لماذا أنت», «لماذا أطلب منك», the review); the platform proposes step *kinds* from real chapters only. A partner sees the *state* of your step (happened / not yet), never your events. Invitations never reveal membership: the same reply whether or not the person is in your circle (blind rows expire silently).
    - **An organization promises only what the platform can witness toward a person** (P30). The four org acts are `seat` (a council seat) · `level` (a level approval) · `attestation` (a peer attestation) · `missions` (confirming the member's missions within 7 days, three in a row). The org's path is derived from events like everyone else's; the manager signs «بصفته» (capacity, not name — the signer is never in the document) and a staff member who is not the org admin can read but never sign.
    - **Accessibility baseline (standing rule since P30): every new page meets WCAG 2.2 AA** — contrast ≥ 4.5:1, a visible 3 px `:focus-visible` ring on every control, text + `aria-label` next to any colour dot (never colour alone), `role=status/alert` for messages with an explicit close button and **no auto-timeout**, labelled `radiogroup`s, touch targets ≥ 24 px, no timed forms. The E2E for each phase asserts at least the dot text and keyboard focus. Since P32 every page also has a skip link first in tab order (`SkipLink` inside `PortalShell` **and** `GlobalNavigation`), dialogs trap focus and return it (`AccessPanel`), and the `<html data-access>` tokens drive CSS (zoom 1.25 for `low_vision`, 44 px targets for `motor`, no motion for `focus`, no autoplay video for `low_bandwidth`).
    - **Who people are is written by them, witnessed by the platform, approved by staff** (P31 «هيئة أَثَر»). A directory profile has two halves that never mix: the CV the member writes (with per-section visibility) and «ما شهده أَثَر», derived from records (legacy trainer assignments, councils chaired, approved levels/attestations, confirmed missions, settled collaborations, the org charter) — hideable as a whole, never editable. **No stars, no ratings, no ranking, no «featured»**: order is `updated_at desc, name`. No email/phone/fee in public, on the card or in any document; requests go through staff (`portal_consulting_requests` + `expert_profile_id`); every assignment is its own signed collaboration agreement `ATH-CO` whose fee is visible to the two parties only. The photo is mandatory for approval with a dated consent renewed per photo; it is copied to the public bucket only on approval and removed on suspension/erasure.
    - **AI reads, the human reviews** (P31-ب): a file the member uploads (CV) is read once, never stored, and only *proposes* fields — empty fields are filled, existing ones kept unless the member ticks «استبدل»; nothing persists before «احفظ»; «تراجع» restores the previous form; closed lists (skills, sectors, services, modes, languages) accept known ids only; the governance log keeps counts, not content. Multimodal attachments go through `runAi({ attachments })` (Gemini `inlineData`; OpenAI `file`/`image_url`; Anthropic `document`/`image`). Word files are unpacked by a hand-written ZIP reader in `lib/directory/cv.ts` — still zero new npm packages.
    - **The same portal adapts; nobody is sent to a separate one** (P32 «أَثَر للجميع» / «أَثَر يلبّي احتياجاتي»). The access profile is written in *needs words* (10 codes in `lib/inclusion/registry.ts` `NEEDS`, e.g. `hard_hearing` «أسمع بصعوبة») — never a diagnosis, never a document, never a reason asked. It is PDPL-sensitive: **it never reaches any AI model** (the only AI touch is a plain-language rewrite of *public* text, and an identity-free `simple` style flag for أثير), it is never shown to organizations, staff see it only aggregated with **k ≥ 5** or for people who explicitly ticked `share_staff` and only in the context of a program they were accepted into (`programNeeds`). Programs declare what they actually provide (`programs.access_features`, 9 codes) and «يناسبني» filters by `fitsNeeds`; nothing is promised in general. Every simplified text («نسخة أبسط») is **pending until a staff member approves or edits it** — the public endpoint returns `null` before that. The `/accessibility` statement has a «ما لم يكتمل بعد» section that must stay honest (مِعيار, sign-language partner, legacy PDFs).
    - **A human is present now, by their own decision — and the platform never speaks for them** (P33 «أَثَر معك — على الهواء», P34 «الهواء يتّسع»). Presence is self-toggled (`portal_onair_presence`, auto-off 90 min), requests have three grades (quick · session in a `support` room · consult → P31 `ATH-CO`), no stars (only «ما الذي تغيّر؟» to the receiver alone), hours come from real meetings (`ATH-OA` at 10 h / 8 meetings). AI ranks the queue and summarizes with the asker's consent; it drafts a «صدى السؤال» daily case that waits for staff approval; it never answers in a human's name. Need-words never enter matching (interpreter seat only with explicit consent in the request); the sign-language dialog defaults are computed in the browser. Org-scoped air (`org_id`) calls confirmed members only; the live map shows cities, never people; a «أمانة الهواء» survives 72 h when nobody is on air; a `shadow` mentee thread is read-only for the mentor and earns no hours. P35 «موسم الهواء» gave the air a calendar without touching those rules: a staff-declared season in which each organization announces one golden hour (`portal_onair_season_slots`, name on the map only with the org admin's consent; season document `ATH-OS` in the org's name after the season), an entrusted question inside an org waits 24 h for its members then becomes public by reading (`org_hold_until`), the echo returns to its people as a count only («صدى يعود», k≥5, steps 5/25/100), a mentor may give the mentee one reverse shadow («ميراث متبادل», witnessed as a fact), a 7×24 density strip per city says *when* the air is usually lit (never how many; city shown from 5 distinct people; log deleted after 90 days), and an approved interpreter may open a public 10-minute «همسة» room for the day's skill in sign language (once a day, counted as a meeting). P36 «ذاكرة الهواء» is what *remains* after the air goes quiet, under the same rules: every finished season leaves one public anonymized «سجلّ الموسم» (`/on-air/seasons/[id]`, frozen once into `record_json` by reading or by the existing cron before the 90-day log is deleted — orgs, cities, densest hours from 5 distinct people, meetings as a band, signed hours only if the interpreter actually came; `.ics` written by hand; MCP `season_record`); an org hour may be «بالإشارة» only with an approved interpreter chosen by the org admin, and members whose private access profile says sign language see signed hours first *on their device* (`<html data-access>`, nothing sent); an entrusted question whose writer ticked «يجوز نشرها» and that nobody claimed in 72 h becomes a candidate for «سؤال الأسبوع» — a staff human edits the wording and approves, one question a week, answered only by people on air, by role not by name, once each, PII scrubbed, the writer notified internally; and the org admin sees a 7×24 «خريطة الزمن للجهة» of their own members (no grid under 5 members, cells under 5 people hatched «أقل من خمسة») with three arithmetic «أنسب ساعات» they may copy into the season form — a suggestion, never a decision. P37 «عُمر الهواء» gives the air an *age* without a single new rule about people: retired week questions that got answers hang on a public «جدار الأسبوع» (`/on-air/week`, answers by role, staff may hide a question, the entrusting writer alone may mark «أفادت صاحبها ✓» once); two orgs — never more — may merge their season hours into one «موسم مشترك» by two-sided admin consent (`shared_with_org_id/shared_status/shared_group`, names together only with both `public_name`s); every calendar year gets a «سجلّ السنة» (`/on-air/seasons/year/[year]`) stitched from frozen season records only (Hijri span in the title via `Intl` `islamic-umalqura`, distinct orgs from 5, no re-reading of deleted logs); and an approved interpreter may pledge one weekly 30–90-minute «مترجم الموسم» hour for a whole season — reminded inside the existing season reminder, shown «الآن» and counted in the record only when they actually come on air.
    - **A credential keeps growing after the program ends — in the learner's own words, honestly** (P38 «الشهادة التي تكبر»). Three stations (+30/+90/+365 days, ±14) per approved enrollment of a finished program; the learner writes what they did and picks one state *in words*; a missed station stays empty and nothing is edited; a witness (never oneself) signs one sentence; chapters reach the living credential only by the learner's choice; the public program box speaks only from five distinct learners, in word bands, never percentages or stars, and excerpts require the author's consent **and** a human's approval; AI only drafts a staff-side summary from anonymized texts.
    - **Voices around the credential answer it, they never replace it** (P39 «أصوات حول الشهادة»). A letter the learner writes to themself in the last week of the program is sealed (nobody — not the author, not AI — reads it) until the year station; a program *responds* with an application workshop only when five distinct people wrote «لم تسنح الفرصة» and only by a human pressing the button (AI drafts from anonymized texts); an organization writes its own one-time station after a year only for programs with ≥5 of its confirmed members, published under its name only with its consent; a مِعيار measurement joins the ATH-AF document only by the learner's choice and the public program line speaks only from five measured learners. Nothing is edited after saving; no counts in public.
    - **The hard moment is rehearsed with a human before it happens** (P45 «بروفة» / official «التمرين التبادلي بين الممارسين»). A signed-in practitioner describes a situation (20–300 chars, PII scrubbed, a 2062 sector), the role they need played (required) and a circle (all · program · need · faculty), now (open 2 h) or scheduled within 7 days (+30 min grace); optional real date. Requests are shown **without name or email**; only an enrolled practitioner, an approved faculty member or staff may «ألعب هذا الدور», never the asker. Accepting reveals both names to the two parties only and opens a `portal_rooms` row of kind `rehearsal` (2 peers, 15 min, role card in `prompt`); either party finishes; each then writes one «جملة طيبة» (≤200, delivered when the other writes or after 24 h) and one «ما سأفعله مختلفًا» (≤300, private, published anonymized only with consent and only when a sector reaches five). No scores, no recording, no AI in the room, no ranking of partners; expiry is lazy, report closes the room and tells staff. New surfaces that know a situation is coming (P38 open station, P44 need, program page, daily case) should offer a prefilled rehearsal.
    - **The report is filled by Athar and judged by the teacher** (P46 «محور التقارير» / official «توثيق الجودة والأداء»). A weekly learning report (`kind='weekly'`) snapshots `computed` from real data (approved `portal_enrollments`, `attendance_sessions`/`records` in Sun→Thu period, `trainers.email` scope, program/template skills) and freezes it as a document; the teacher writes the eight sections (goals · activities · formative/summative assessment · per-student 0–100 skill grid with computed grade 90/80/70/60 · recommendations · strengths · admin notes) plus an optional private line per trainee; `missingBeforeSubmit` lists six requirements; staff `approve`/`return{note}` (one stage, `programs.write`); approval mints `R`+9 verify code (public view has no student names/scores) and sends lines only if `lines_ok`. AI purpose `report_phrase` returns descriptive sentences from numbers only (`parsePhrases` rejects grade/recommendation words; `localPhrases` fallback). **ر2 (shipped): the final report (`kind='final'`, one per classroom) is built from the approved weeklies** (`computed.weeks` with their verify codes = «سلسلة الثقة», `computed.trajectory` per trainee = week averages/delta/trend); the matrix sorts by progress not grade; recommendations are suggested (`suggestRec`, never `repeat`) and decided by the teacher; approval needs **two signatures** (`approve{as:'quality'|'manager'}`, different people unless platform admin; `return` clears `body.signoff`); the second signature mints the code and writes `portal_report_lines(kind='final', data=studentPageData, verify_code)`; the trainee sees only `/me/reports/line/[id]` and may toggle `show_on_credential` so `/credential/[code]` shows the path paragraph (`/api/reports?credential=`); staff `promote{program_id}` turns «promote» recommendations into pending `portal_enrollments(source='report')`. ر3 mission report and ر4 diploma file are deferred and reuse the same tables.
    - **The catalog is written from need, never from the office** (P44 «البرنامج الذي لم يُكتب بعد» / official «الاحتياج التدريبي المعلَن»). A signed-in practitioner writes a need in one sentence (20–200 chars, PII scrubbed, a 2062 sector); it stays a *seed* visible to signed-in users until **five people other than the author** say «وأنا أيضًا», then it is public **without any name**. Only an approved Athar-Faculty member or staff may *adopt* it (pitch ≤ 600) — adoption creates a real `portal_program_drafts` row (`need.need_id`), staff finish and publish it in program engineering, publish sets `programs.born_from_need_id` and the program page says «وُلد من حاجة أعلنها N ممارسًا». Declarers get **the first seats for 72 h** after registration opens (lazy on first program-page visit; DB trigger guards `portal_enrollments`). No ranking by support count, folding after 90 days is quiet and reversible, AI never writes/adopts/approves a need. Every new learner-facing surface that discovers a gap («لم تسنح الفرصة», catalog empty state, org impact tab, P39 offers with five «أرغب») must link into `/needs`.
    - **Not «تقليدي».** The owner rejects dashboards/tables/reports as the shape of new features. Build experiences (story chapters, rooms, mirrors, councils, letters to one's future self); official terminology stays in admin/contract surfaces.
    - **Every interaction accepts text, voice or video** through the single `Channel` component (`app/components/Channel.tsx`, media in `portal_media`).

## 4. Roles & auth
- `PLATFORM_ADMIN, SUPER_ADMIN, ADMIN, PROGRAM_MANAGER` = writers; `+ QUALITY_ANALYST` = staff (`STAFF` arrays in routes); `TRAINER`; learners authenticate by email OTP/password and own rows via `auth.uid()`.
- **Since P42-a two layers coexist.** New code should authorize with `myRoles(db, user)` / `hasPermission(codes, 'ns.action')` from `lib/portal/roles.ts` (or SQL `portal_has_role('CODE')`), not with `profiles.role`. Legacy ENUM checks keep working because every grant upgrades `profiles.role` to the minimal legacy level (`legacy_role` in the catalog) and never downgrades. The owner's access model: staff accounts exist only by admin invitation (`/admin/roles` → `/join/<token>`); learners self-register by email (role PARTICIPANT implicitly); trainers/experts come through هيئة أَثَر (`portal_directory_profiles.status='approved'` → automatic TRAINER/EXPERT grant is a P42-b item). Landing after login: `landingFor` (ADMIN → `/dashboard`, one door → that door, several → `/hub`, none → `/me`). Doors are `/hub/<leadership|programs|diplomas|quality|operations|finance|expert|trainer>`.
- Route pattern: `Authorization: Bearer <access_token>` → service client `auth.getUser(token)` → `profiles.role/full_name`. Delegated agents arrive with the `X-Athar-Delegate` header (`delegateFromHeaders`) and a scope (`wallet:read | daily:write | missions:read | snapshot:issue | council:write`) — **agents read; only the person writes/publishes**.
- Org admins: `portal_org_members.role='org_admin' and status='confirmed'` (`isOrgAdmin`). Organizations are created by SQL only (no UI by design — `phase6-p28/900-b-first-org.sql.txt` pattern: insert `portal_organizations` + a confirmed `org_admin` row with `source='admin'`); `/org` shows «لست مدير جهة بعد» when the user has no confirmed org_admin membership and is not staff.
- Two Supabase clients in every route: `userDb` (anon key + the user's Bearer → `auth.uid()` works, RLS applies) for RPCs that authorize internally, and the service client for table access after the route authorized the caller itself.

- **AI output mode.** `callWithFallback`/`runAi` force JSON output by default (`response_format json_object` / `responseMimeType application/json`). Free-text answers (e.g. «اسأل أثير» in `app/api/search`) MUST pass `json: false` — OpenAI rejects `json_object` when the prompt lacks the word “json”, which silently fell back to the local answer on production until P42-b.
